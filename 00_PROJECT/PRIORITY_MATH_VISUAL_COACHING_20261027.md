## 2. 문제 정의
현재 Math 첨삭은 결과를 단순 텍스트로 나열하여 수식 구조·원본 풀이 위치·오류의 인과관계·단계 코칭이 학생에게 충분히 전달되지 않는다. 수학적 정확성도 실학생 데이터로 검증되지 않았으므로 유료 자동첨삭 수준이라고 판단하지 않는다. **렌더링 개선과 수학적 판정 정확성 개선은 별개의 과제**다.

### Manus (2026-10-27 심층 벤치마크; 사용자 제공 보고서)
- **직접 관찰/공식 주장/과거 공식 기술근거/추정/미확인**을 분리한다. 콴다의 문제 분리·전략→접이식 단계 UI는 공개 화면으로 관찰. 스쿨작 지정 네이버 글은 **문항 입력→대안 풀이→풀이 비교→학생 재작성→교사 최종 첨삭** 흐름을 서술. 수작은 학원용 문제은행·OCR/자동해설 주장. **어느 제품도 자필 장문 수리논술의 신뢰 가능한 자동 부분점수·재첨삭 정확도가 공개 검증된 것은 아님.**
- 권고 파이프라인: **원본 불변 보존→영역 좌표(region)→수식 전사 후보·학생 확인→풀이 step/DAG→제한 CAS 검증→ROOT 오류·조건부 판정→최소 힌트→재작성→성장 측정**.
- 수학 판단은 `valid / invalid / conditional / unknown` 구분. OCR 오독을 학생 오류로 오판하지 않음. 대안 풀이 인정, 공식 루브릭·조건·정의역 확인. SymPy는 산술·조건부 동치·후보해 대입 등 제한 범위. Lean은 후속 연구.
- 학습효과는 단순 재첨삭 점수 상승이 아니라 **힌트 의존도·무힌트 병렬문항·지연 전이**로 검증. 교사 검수 골드셋, 개발/검증/잠금 테스트 분리 권고. Manus 보고서의 비용·일정·성능 수치는 실제 측정이 아닌 가정/목표.
- 자료: `AI 수학 튜터링 심층 벤치마크: 레전드스터디 수리논술 코칭·검증 설계`, `feature_comparison.csv`, `poc_cost_model.csv`, 공식 화면 번들.
