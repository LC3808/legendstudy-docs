# 논술 LAB 평가 전략 변경 — 대학별 첨삭 프로필 중심 (Owner 결정)
작성: 2026-10-23 · 상태: 전략 확정 / 구현은 3단계 검증 후 진행

## 결정
기존의 모든 문항에 단일 평가기준을 강제하는 방식을 중단한다. **공통 서비스 UX와 실행 인프라**는 유지하되 **평가 판단 기준**은 `공통 엔진 → 대학·논술유형별 프로필 → 학년도·전형 예외 → 문항별 공식 근거 → 학생 답안`으로 조립한다. 대학별 프로필은 반복 활용하고, 문항별 해설·정답·핵심 논점은 반드시 해당 문항의 자료를 사용한다. 공식 기준이 바뀌지 않았다는 추정만으로 연도 전체에 일괄 적용하지 않는다.

## 목표와 범위
- Owner 확정 누적 서비스 대학 수: **1차 11개 → 2차 22개 → 3차 30개 → 4차 35개 이상**. 각 단계의 신규 추가 대학 수가 아니다.
- 기존 한양대 인문·건국대 인문/수리·숙명여대 이미지 평가 성공 경로를 재사용한다.
- 사용자 화면의 문제 선택, 답안 입력, 결과·재첨삭·History·Credit UX는 공통 유지. WEB/Flutter Native APP 동일 Backend.
- 경희대·동국대의 별도 누락자료 보강 HOLD는 유지. 신규 자료 재업로드 및 기존 ID 교체 금지.
- 기존 성공 E2E, 답안, Ledger, RLS, PDF 및 실행 정책을 보존. 기존 AI HOLD를 임의로 전체 해제하지 않는다.

## 평가 입력 우선순위
1. **문항별 공식 채점기준·정답·출제의도·해설** (실제 확인된 것)
2. 해당 학년도·전형·계열의 공식 예외
3. 대학·유형별 버전 관리된 평가 프로필
4. 공통 인문/수리 평가 계약

상충 시 상위 근거를 사용하고 출처·적용 범위·확인일·검수 상태를 남긴다. 없는 배점/공식 기준을 만들어내지 않는다. 대학 프로필은 '어떻게 평가할지', 문항 근거는 '무엇이 맞는지'를 결정한다.

## 프로필 최소 스키마(논리 계약, DB 신설 지시 아님)
- university_id / 논술 유형(인문·상경·수리·특수 세부유형)
- profile_id / version / status(DRAFT, REVIEWED, ACTIVE) / applicable_years / admission_types
- 공식 출처 목록·근거 페이지·확인일 / 검수자·검수일
- 평가역량·가중치(공식 확인 시에만 공식값) / 감점·부분점수 원칙 / 답안 분량·형식 / 피드백 스타일
- 연도별 override / 문항별 rubric·answer·explanation 연결 / fallback 규칙 / 변경 이력
- 실행 시 사용된 profile_version·question_package_version을 History에서 추적 가능하도록 한다(기존 필드 우선 재사용).

## 3단계 실행 및 Owner 게이트
### PHASE 1 — 기존 자산 조사·프로필 규격·샘플 제작
Wiki 최신 Authority와 운영 계약을 읽고 기존 스키마/Registry/Worker의 재사용 가능성을 확인한다. 한양대 인문, 건국대 인문·수리, 숙명여대 이미지 사례로 프로필 템플릿을 작성한다. 11개 대학·유형별 보유 근거, 부족한 근거, 연도별 예외를 표로 정리한다. **코드·DB·Production 변경 없음.** 결과와 2단계 최소 변경안을 Owner 검토 후 진행.

### PHASE 2 — 기존 엔진에 프로필 조립 연결
Owner가 1단계를 확인하면 기존 평가 입력 계약에 프로필 선택·문항별 override를 최소 변경으로 연결한다. 기존 성공 E2E를 회귀 검증하고 11개 대학의 근거 있는 프로필을 채운다. 먼저 로컬/격리 테스트, 다음 승인된 범위의 운영 E2E. 실패 문항은 증거와 수정 명세로 분리한다. **Owner 검수 후 3단계 진행.**

### PHASE 3 — WEB/APP 실서비스 적용·22개 대학 확대
검증된 문항을 WEB·Flutter APP에서 실제 평가·재첨삭·History·Credit 1/0까지 확인하고 점진적으로 활성화한다. 공통 UI 유지, 평가 내용은 대학별 프로필 적용. 활성 문항 수·평가 품질·실패율을 대학별로 보고한다. 이후 동일 프로필 제작 절차를 우선순위 22개 대학으로 확장한다. 전체 512문항 자동 PASS 금지.

## 완료·보고 원칙
각 단계별 PASS/PARTIAL/FAIL과 실제 검증 범위를 구분. 성공 구현 재사용 여부, 프로필 수/유형/근거, 문항 매핑 수, 연도 예외, 실제 E2E, Credit·History, 실패 명세, Owner 판단 사항, 커밋/원격 SHA를 보고한다. 문서 PASS는 서비스 PASS가 아니다.

## 제품 North Star
“한 번도 사용하지 않은 사람은 있어도, 한 번만 사용한 사람이 없도록.” 학생에게 대학별로 정확한 피드백과 재작성에 따른 성장 경험을 제공한다. **공통 UX, 대학별 평가, 문항별 근거.**

## Owner 최종 명확화 — 2026-10-23
대학·유형별 기본체계를 먼저 검수하고 기존 문항에 상속한다. 512개 독립 프로필을 만들지 않는다. 변경이 검증된 학년도·시험만 보정하며 문항 고유 기준을 우선한다. PROFILE_READY/PROFILE_MAPPED/QUESTION_EVIDENCE_READY/EVALUATION_READY/E2E_PASS를 분리한다. 공통 역량 진단 범위와 문항 정답 정확성 평가 범위도 분리한다. 기존 운영·UI·Credit·History는 보존한다. ## Owner 확정 — 누적 서비스 확대 로드맵 (2026-10-23)

| 확대 차수 | 누적 서비스 대학 수 |
|---|---:|
| 1차 | 11개 |
| 2차 | 22개 |
| 3차 | 30개 |
| 4차 | 35개 이상 |

- 이 차수는 개발 PHASE 1·2·3과 별개다. **현재 11개 대학의 PHASE 2를 먼저 완료**한다. 목표 대학 수는 현재 서비스 완료 실적이 아니다.
- 기존 대학별·유형별 프로필과 검증 결과를 재사용한다. 22개 대학으로 확대하기 위해 기존 11개 대학 작업을 다시 수행하지 않는다. 변경 영향이 있는 범위만 회귀 검증한다.
- 신규 대학은 해당 대학의 공식 평가체계를 추가하고, 학년도·시험별 특성 및 문항별 공식 근거를 결합한다. 기존 시험·문항·평가자료를 최대한 재사용한다.
- 학생 UI/UX는 공통으로 유지한다. 대학별 새 UI·서버·평가 엔진을 만들지 않는다.
- 대학별 대표 문항에서 실제 평가 E2E를 검증하고 정상 작동하는 문항부터 서비스에 반영한다. 대표 문항 성공을 해당 대학 전체 문항의 PASS로 확대하지 않는다.
- 이번 결정은 확대 순서 확정이다. 2차 이후 구체 대학 명단·일정 및 미검증 문항의 활성화를 임의로 확정하지 않는다. 기존 운영 승인·검수 조건을 유지한다.
- 이전의 ‘약20개’, ‘장기30~40개’ 목표 수치는 이 로드맵으로 대체한다. 대학별 깊이·평가 품질 우선 원칙은 유지한다.
