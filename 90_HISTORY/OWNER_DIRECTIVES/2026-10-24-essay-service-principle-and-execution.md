# OWNER DIRECTIVE — 논술 LAB 서비스 본질 및 대학 단위 실행 원칙 (2026-10-24)

**상태: OWNER 확정 / 다음 개발 세션 시작 전 필독**  
**범위:** LegendStudy 논술 LAB의 Essay·Math 평가 연결, 검증, 운영 공개  
**목표:** 2022학년도 이후 등록된 대학별 시험·문항을 학생이 실제로 첨삭받을 수 있게 연결

## 1. 서비스의 본질

논술 LAB은 **모든 문항에서 완벽한 모범답안을 재현하거나 정답을 판정하는 시스템이 아니다.** 학생이 작성한 답안을 **해당 대학·시험·문항의 문제, 출제의도, 평가기준, 채점기준**에 비추어 검토하고, 잘한 점·부족한 점·구체적인 개선 방향을 제공하여 재작성과 성장을 돕는 서비스다.

학생 흐름: 문제 확인 → 답안 작성·제출 → 기준에 따른 첨삭 → 강점·보완점·개선 방향 확인 → 재작성·재첨삭 → 성장 기록.

내부 평가 엔진에는 공식 자료와 대학별 프로필을 사용한다. 일반 사용자 화면에는 **'AI', 'AI 첨삭', 'AI 생성', '대학 예시답안', '대학 공식 예시답안'** 등을 노출하지 않는다. 내부 공식 예시답안은 평가 근거로만 활용하고 재배포하지 않는다.

## 2. 평가 구조

- **대학·유형별 기본 평가 프로필**은 재사용한다.
- **학년도·시험별 예외**는 공식 근거가 확인될 때만 추가한다.
- **문항별 공식 자료**(문제·출제의도·평가기준·채점기준·해설 등)는 정확한 시험·문항 ID에 연결한다.
- 기존 Essay·Math Worker, 제출·Credit·History·WEB/APP 공통 계약을 재사용한다.
- 학생에게는 대학과 관계없이 일관된 첨삭 결과·재작성·성장 경험을 제공한다.

## 3. 검증 원칙 — 과도한 개별 반복 금지

**모든 문항에 실제 Provider 평가·재첨삭·Credit·WEB/APP 전체주기 E2E를 반복하는 것을 공개의 기본 선행조건으로 삼지 않는다.**

대신 다음을 분리한다.

1. **공통 서비스 계약:** 제출·멱등성·Credit·History·WEB/APP 동기화. 변경 영향이 없으면 기존 성공 검증을 재사용한다.
2. **대학·유형별 평가 계약:** 해당 유형의 대표 사례로 품질과 입력 계약을 확인한다.
3. **문항별 전수 확인:** 문제 PDF, 출제의도, 평가·채점기준, 문항 ID, 입력 조립 및 권한 연결의 정확성을 검증한다. 실제 Provider 반복 호출은 기본값이 아니다.

학생 답안은 불완전할 수 있으며, 그것을 분석하고 개선 방향을 제시하는 것이 서비스 목적이다. 단, **자료 오연결, 타 문항 근거 혼입, 허위 채점 근거, 보안·Credit·History 무결성 문제는 용인하지 않는다.** 공식 기준이 부족하면 가능한 진단 범위를 정직하게 제한하고, 정답·배점을 지어내지 않는다.

## 4. 대학 단위 실행

작업 단위는 대표 문항 하나가 아니라 **해당 대학의 등록된 전체 학년도·시험·유형·문항**이다.

대학 전체 Registry 확인 → 프로필 상속 → 문항별 공식 자료 일괄 연결 → 입력 전수검사 → 유형별 대표 E2E → 검증된 문항 묶음 활성화 → 미완료 문항 별도 기록 → 다음 대학.

목표는 하루 1개 대학(가능하면 2개)이나, 이는 일정 목표이며 검증 생략을 허용하지 않는다. 대학 전체 등록 문항을 분류하되 정상 문항부터 공개하고, 보류 문항이 있으면 대학 전체 완료라고 보고하지 않는다.

## 5. 오류 A/B/C 분류 및 중단 규칙

- **A — 공통·중대 장애:** 인증, 권한, 개인정보, Credit·Ledger, History 무결성, 공통 Worker 장애. 즉시 대응·필요 시 운영 중단.
- **B — 대학·유형별 오류:** 해당 범위를 격리하고 다른 정상 범위 진행.
- **C — 개별 문항 오류:** 원인 확인과 최소 수정은 **30분 목표**. 해결되지 않으면 증상·재현 조건·영향 범위·근거·추정 원인·후속 조치를 기록하고 다음 문항으로 이동. 중대 무결성·보안 이슈는 예외.

이미 성공한 동일 계약을 이유 없이 다시 검증하지 않는다. Provider 반복 호출은 변경 가설과 성공 기준이 있을 때만 수행한다.

## 6. 성과 및 운영 공개

최우선 성과는 **새로 일반 공개된 대학·시험·문항 수**다. 테스트 수·Provider 호출 수·커밋 수·문서 수는 보조 지표다. 등록/프로필 상속/입력 준비/대표 E2E/일반 공개를 구분해 보고한다.

일반 공개는 실제 운영 승인과 문항별 근거·입력 검증을 통과한 범위만 수행한다. 문제 PDF는 기존 권한대로 열람시키고, 미연결 문항은 **'첨삭 서비스 준비 중'**으로 표시한다. UI 비활성화만으로 보안을 대체하지 않는다.

**Production SQL은 Owner가 직접 실행한다.** Codex는 precheck/apply/postcheck/rollback을 준비하고 운영 데이터·기존 ID·Credit·History를 보존한다.
