## ACCOUNT-DELETION-PRODUCTION-ACTIVATION — 완료 (destructive E2E PASS, 웹 LIVE)

ADR-2 계정 삭제 파이프라인을 Production에서 활성화하고 synthetic 계정 `test1@legendstudy.com`으로 파괴적 E2E를 통과시켰다.

### 활성화 구성 (Production)
- Owner가 privileged write 실행(Option 2): Edge+Vault `account_dispatch_secret` 동기화, `ACCOUNT_LIFECYCLE_ENABLED=true`, `ACCOUNT_FINANCE_REVIEWED=true`, `ACCOUNT_EMAIL_REAUTH_ENABLED=true`, `ACCOUNT_RESTORE_CHECKPOINT_URL`/`ACCOUNT_NOTIFICATION_URL`→`account-ops-sink`, `ACCOUNT_OPERATIONS_TOKEN`.
- `dispatch` pg_cron 매분 실행(`legendstudy_account_deletion_dispatch_worker`, Vault bearer). dispatch가 매 사이클 `account_deletion_maintenance`(만료 receipt/reauth purge + heartbeat)를 수행하므로 **별도 watchdog cron 불필요**.
- `dispatch_health.enabled=true`.

### 디버깅으로 밝힌 근본 버그 3개 (app `d95b983` + migration `20261006000100`)
1. **worker 인증**: worker가 `apikey=anon + Bearer=커스텀 account_lifecycle_worker JWT`로 PostgREST를 호출 → 거부. 프로젝트가 **ES256 비대칭 JWT 서명으로 이전**되어 legacy HS256 커스텀 role 토큰을 수락하지 않음. 이미 정상 동작하는 `process-feedback-notifications`와 동일하게 **`SUPABASE_SERVICE_ROLE_KEY` 재사용**으로 전환(worker가 실제 호출하는 **22개 `account_*` RPC에만** service_role EXECUTE grant — broad grant 금지).
2. **`account-ops-sink` shadowing**: `const URL = Deno.env.get("SUPABASE_URL")`가 전역 `URL` 생성자를 가려 `new URL(req.url)`가 TypeError → `/checkpoint` 500. dispatch는 `claim` 전에 checkpoint 웹훅을 치므로 **전체 파이프라인이 AUTH 이전에서 막혀 아무것도 삭제되지 않았다**. `SB_URL`로 개명하여 해결.
3. **Math FK**: `math_attempts.student_id → profiles`가 **RESTRICT**. ADR-2는 Math 스키마보다 먼저 설계되어 `auth.users`→`profiles` cascade 삭제에 의존하는데, RESTRICT가 profiles 삭제를 막아 GoTrue admin user-delete가 **500 / `AUTH_UNAVAILABLE`**. migration `20261006000100`으로 **RESTRICT→CASCADE** (essay_practice_sessions/student_target_universities와 동일 패턴; profiles 삭제는 계정삭제 때만 발생).

### E2E (test1@ = 713e3e4f, synthetic)
REQUEST → CANCEL + **email reauth**(비밀번호 재확인 방식) → RE-REQUEST → **deadline 가속(test1 요청 1건만)** → 파괴적 worker → `ERASED`/`DONE`.
- 가속은 `requested_at`과 `scheduled_deletion_at`을 **함께** 과거로 이동해 `scheduled_deletion_at = requested_at + 336h` CHECK를 유지(immutable 트리거는 트랜잭션 내에서 잠깐 해제). **336h 상수·글로벌 정책 불변.**
- **검증:** `auth.users` test1 삭제, `profiles` 삭제, `math_attempts` 7 / `math_evaluations` 7 + 모든 CASCADE 자식 삭제, 타 사용자 Math(2건) 미접촉, credit 계정 **de-identify 보존**(`user_id`→NULL, grants/txns 유지 = FINANCE phase 의도된 금융 보존), 요청 `subject_id`→NULL, **30일(720h) ERASED receipt**.

### Storage byte-erasure (정확한 표현)
- test1은 **타이핑 Math 입력**이라 삭제 전 Storage object = 0, 삭제 후 orphan object = 0.
- byte-erasure **메커니즘은 적용**되어 있으나, 이번 synthetic case에는 **기존 바이트 1→0 파괴 증거가 없다**(과장 금지).
