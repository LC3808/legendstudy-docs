# 논술 LAB — 출시·베타·수리 코칭 Owner 결정 (2026-10-26)

## 최상위 원칙
- 서비스의 핵심 가치는 정답 판정이 아니라 **첨삭 → 재작성 → 재첨삭 → 성장**이다.
- 이미 완료한 작업을 반복하지 않고 기존 Registry, 공식자료, Worker, Credit, History, Ledger, 공개 정책을 재사용한다.
- STANDBY(문제/PDF/답안 입력/첨삭 요청 경로 연결)와 실제 E2E 성공, 정식 공개를 구분한다.

## 1. 출시 및 베타 정책
- 1차 출시 준비: 1·2·3순위 대학의 확보된 인문·사회·상경 장문형 회차. 대학 전체가 아닌 **회차/문항 구성 기준**으로 활성화한다.
- 자연·의예·과학 수리논술: 정식 유료 첨삭 비활성화. 기존 데이터·성공 결과 보존.
- 수리문항이 포함된 사회·상경 혼합형: 평가·코칭 품질이 확인된 회차만 베타/출시 후보; 나머지는 보류. 수리문항을 빼고 전체 회차 첨삭으로 판매하지 않는다.
- 인문·사회·적격 상경 베타: **5일 기본, 최대 7일**, Owner가 실제 품질 확인 후 유료 전환.
- 베타 프로모션: **로그인 사용자의 당일 첫 접속에 하루 2 Credit 자동 지급**, 한국시간 00:00 리셋, 미사용분 당일 만료, 이월 없음. 신규가입 무료 3 Credit·유료 Credit과 구분해 보존. 차감 우선순위 베타→가입 보너스→유료. 기존 회차당 최초 1 Credit, 기존 무료 재첨삭 0 Credit/14일 계약 유지.
- 기존 Ledger의 출처별 잔액·만료·예약·환불 지원 여부를 먼저 조사. 지원되지 않으면 **설계안만 보고하고 승인 없이 정산 계약 변경 금지**. 자정 이전 예약된 요청은 처리 완료 가능해야 하며 다른 출처 잔액을 만료시키지 않는다.
- 자연계 수리논술 무료 코칭 베타는 **별도 후속 결정**, 현재 베타 지급 대상이 아니다.
- 답안 입력 안내: “답안에는 이름, 수험번호, 연락처 등 개인정보를 입력하지 마세요.” 서비스 제공과 품질 개선 데이터 활용은 정책에 맞게 구분한다.

## 2. 이번 자료 연결 작업
- 기존 material 폴더의 2·3순위 대학과 이미 생성된 Registry를 대조하여 누락 없는 회차 단위 STANDBY를 만든다.
- 우선 확인 대학: 숙명여대, 한국항공대, 광운대, 숭실대, 동국대. 기타 2·3순위는 **Unified Wiki 우선순위표**를 기준으로 정한다. 서울여대 기존 예외 및 이화여대 자료 부족 여부를 보존/보고한다.
- 공식 시행 시험만 등록; 2022~2027학년도 중 확보 자료(2027 모의 포함) 기준. 실제 문항·소문항, 문제 PDF, 공식 해설·평가기준, 입력 UI, Essay/혼합형 경로를 연결한다.
- 기존 시험·문항 ID, PDF 해시, SQL 적용 이력 재사용. 목록만 만들고 끝내지 않는다.
- 학생 일반 계정에서 시험 선택→전체 문항/PDF→답안 입력·저장→서버 승인 기반 첨삭 버튼/1 Credit 확인창까지 점검한다. **Provider 실제 평가·Owner QA는 Owner가 별도 수행**.
- 완료 회차/보류 회차/누락 자료/활성·비활성 공개 상태를 대학별로 보고한다.

## 3. 수리논술 장기 방향 — 풀이 코칭
- 원본 이미지 + 추출 텍스트/수식 + 공식 문제·해설·평가기준을 함께 활용하는 하이브리드 평가 검토.
- 학생이 막힌 단계, 누락 조건, 계산·개념 오류를 찾고 **다음 풀이 힌트 → 수정 과정 → 재작성**으로 연결한다.
- 수학 수식은 LaTeX/수식 렌더링, 원본 이미지와 텍스트 설명을 병행. 근거 없는 원본 이미지 좌표 강조는 금지.
- 완성형뿐 아니라 부분 완성·중도 포기·오류 포함 답안으로 평가·코칭 품질을 검증한다.
- 기존 Math Worker, Registry, Credit, History를 보존하며 별도 PoC 후 Owner 승인하에 개발. 자연계 유료 공개는 보류.
- 음성 피드백은 TTS 엔진과 수식 읽기·쉼표·문장 분할·한국어 발음 개선을 별도 과제로 검토한다.

## 4. 실제 답안 기반 첨삭 — 미반영 요구사항
- 추상적 평가문 대신 **학생이 실제로 쓴 표현을 짧게 인용**하고, 문제점·이유·수정 방향을 연결한다.
- 답안 원문을 보존하면서 “수정된 문장 보기” 토글에 **구체적인 개선 문장 예시**를 숨겨 두고 사용자가 선택적으로 펼친다.
- 예시는 학생의 주장을 대신 창작하거나 공식 모범답안으로 가장하지 않는다. 근거와 의미를 유지하며 과도한 정답 대필은 피한다.
- 원문→개선 예시→개선 이유를 문항별로 연결한다. 데이터/Worker 지원 여부를 확인한 후 구현 범위 보고; 기존 History 임의 변조 금지.
- 성장 비교와 재작성 CTA를 중심으로 학생의 다음 행동을 명확히 한다.
